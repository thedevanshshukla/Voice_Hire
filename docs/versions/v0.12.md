# Version 0.12.0 — Memory & Cross-Turn Synthesis

## 1. Objective
Implement short-term conversational working memory (capturing candidate claims, synthesizing natural cross-turn references, detecting factual contradictions) and long-term multi-round candidate profiling to track candidate growth and avoid repeating questions across rounds.

---

## 2. Previous Architecture (v0.11.0)
- The system utilized Knowledge Base RAG for company standard retrieval.
- However, it lacked persistent working memory across turns within a session and did not maintain multi-round candidate profiles.

---

## 4. Changes Implemented
- **Memory Schemas (`backend/app/models/interview.py`)**:
  - `ClaimEntity`: Records candidate architecture choices and statements.
  - `ContradictionItem`: Flags conflicting statements with explanations.
  - `ShortTermMemory`: Active working memory container.
  - `CandidateProfile`: Multi-round profile tracking round progression and cumulative strengths.
- **Memory Engine (`backend/app/interview/memory_engine.py`)**:
  - `InterviewMemoryEngine`: Extracts claims (Postgres, Redis, Kafka, Lock types), compares new answers against earlier statements to flag contradictions, and synthesizes natural cross-turn callbacks.
  - `CandidateProfileRepository`: Aggregates candidate sessions across multiple rounds.
- **Prompt Grounding (`backend/app/interview/prompt_builder.py`)**:
  - Injects `[CONVERSATIONAL MEMORY & EARLIER CLAIMS]` and `[LONG-TERM CANDIDATE PROFILE]` into system prompts.
- **REST APIs & WebSockets (`backend/app/api/endpoints.py`)**:
  - `GET /api/interview/session/{session_id}/memory`
  - `GET /api/interview/candidate/{candidate_id}/profile`
  - WebSocket emits `contradiction_detected` event.
- **Frontend UI (`frontend/src/components/VoiceRoom.tsx`, `index.css`)**:
  - Memory Claims Pill in HUD.
  - Contradiction Warning Alert Banner.
- **Automated Test Suite (`backend/tests/test_memory_engine.py`)**:
  - 50 total automated tests passing.
