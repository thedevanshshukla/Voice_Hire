# Version v0.1.0 - Project Foundation

## 1. Objective
Establish a clean, scalable monorepo skeleton, configure backend/frontend Docker environments, implement configuration management, write a structured logger, and build a basic health check API with a beautiful frontend landing page showing connection status.

## 2. Previous Architecture
None. This is the first version of the project.

## 3. New Architecture
```
                     ┌──────────────────────┐
                     │      Candidate       │
                     │    Browser (SPA)     │
                     └──────────┬───────────┘
                                │
                          HTTP / CORS
                                │
                     ┌──────────▼───────────┐
                     │    FastAPI Server    │
                     │    /health Check     │
                     └──────────┬───────────┘
                                │
                     ┌──────────▼───────────┐
                     │    Structured Log    │
                     │      (Console)       │
                     └──────────────────────┘
```

## 4. Changes
* Created `backend/` directory with `FastAPI` startup file (`app/main.py`), settings management (`app/config.py`), structured JSON formatter (`app/core/logger.py`), and health endpoint (`app/api/endpoints.py`).
* Created `frontend/` directory initializing Vite + React + TypeScript, loading premium fonts, and styling a custom dark landing page with real-time API health polling status.
* Added Docker configuration including `backend/Dockerfile`, multi-stage `frontend/Dockerfile`, and `docker-compose.yml` orchestrating both services.
* Established configurations like `.gitignore` and `.env.example`.

## 5. Concepts Introduced
* **Monorepo Architecture**: Separation of presentation layer (`frontend`) and API/agent worker processing layer (`backend`).
* **Structured Logging**: Unified log formats using standard JSON structures for production monitoring and clean formatted consoles for local testing.
* **Environment-Driven Configuration**: Setup validation via `pydantic-settings` to fail-fast if environment configs are missing or malformed.

## 6. Why Those Changes Were Required
To ensure we start building on top of a robust production-grade foundation with clean boundaries, automated containerization builds, and observability from day one, rather than trying to retrofit this into a large codebase later.

## 7. Tests
* **Manual Verification**: Launching services locally and via Docker Compose to check service startup.
* **API Health Check**: Checking that requesting `GET /health` returns JSON success with environment/version payload.
* **CORS Verification**: Making sure the frontend can request the health status from a different port (`8000`) without being blocked by CORS policies.

## 8. Results
* Backend API started successfully and responded to `/health`.
* Frontend built successfully and correctly reflected API status as "Online" (green glow) when backend was active and "API Offline" (red glow) when backend was stopped.
* Docker builds compiled and launched both containers smoothly.

## 9. Known Limitations
* No voice streaming, WebRTC, LiveKit connections, or AI evaluations are implemented yet. These are scheduled for future iterations.
